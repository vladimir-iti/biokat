# биокат.рф

Сайт ГК «Биокат» — инженерные системы объектов.

Next.js (App Router) + TypeScript + Tailwind CSS 4, статический экспорт.
Хостинг — Beget: Apache отдаёт готовые HTML, форма обрабатывается одним PHP-файлом.
Node-процесса на сервере нет.

## Команды

```bash
npm install
npm run dev      # разработка, http://localhost:3000
npm run build    # продакшен-сборка в out/
npm start        # отдача собранной статики, http://localhost:3000
npm run lint     # ESLint (flat-конфиг в eslint.config.mjs)
npm run images   # пережать изображения (запускать после добавления фото)
```

`npm start` поднимает маленький статический сервер (`scripts/serve.ts`) —
он отдаёт `out/` так же, как это будет делать Apache: индексный файл каталога,
свой 404, длинный кэш для хэшированных ассетов. `next start` здесь неприменим:
при `output: 'export'` серверной части у сайта нет.

Важно: `npm run build` и `npm run dev` используют одну папку `.next`.
Перед сборкой останавливайте dev-сервер, иначе он сломается.

## Структура

```
app/          маршруты, метаданные, sitemap и robots
components/   layout / ui / blocks / project / motion
content/      весь контент сайта в типизированных файлах
lib/          типы, выборки, форматирование, SEO-хелперы
public/       документы, изображения, .htaccess
scripts/      подготовка изображений
assets/photos фотографии объектов (см. ниже)
```

## Контент

Правится в `content/`, база данных не нужна:

- `services.ts` — 7 направлений;
- `projects.ts` — объекты; `slug` попадает в адрес страницы;
- `contracts.ts` — реестр договоров из справки о компании;
- `documents.ts` — допуски и файлы для скачивания;
- `company.ts` — контакты и реквизиты;
- `nav.ts` — меню.

Связи считаются на сборке в `lib/queries.ts`. Сумма договора живёт только
в `contracts.ts` — карточка объекта подтягивает её по номеру.

## Фотографии объектов

Сейчас обложки генерируются: схематичный рисунок в фирменной графике,
разный для каждого объекта. Чтобы поставить настоящее фото:

1. положите файл в `assets/photos/<slug>.jpg` (slug из `projects.ts`);
2. выполните `npm run images` — скрипт сделает AVIF/WebP/JPEG в трёх ширинах;
3. пересоберите сайт.

Фотография всегда имеет приоритет над сгенерированной обложкой.

## Производительность прокрутки

Три вещи, которые нельзя возвращать без замены, — каждая стоила кадров:

- **шину ведёт один rAF-цикл** (`BusRail`). За кадр — одна запись `transform`
  на composited-элемент и сравнение позиций узлов: ни раскладки, ни отрисовки.
  Цикл засыпает, как только полоса догнала цель. Отдельные библиотеки анимации
  не нужны: `gsap` и `motion` удалены, ничего их не импортирует;
- **тональная обработка фотографий запечена в файлы** (`scripts/images.ts`).
  CSS-фильтр на картинках пересчитывался при каждой перерисовке кадра;
- **у шапки нет `backdrop-filter`** — размытие подложки на всю ширину экрана
  пересчитывалось каждый кадр. Вместо него полупрозрачный фон.

## Шина

Сквозная линия слева — единственная сложная анимация на сайте. Устроена так:

- `BusRail` — вертикаль. Отрезок вверх от первого узла нарисован всегда, вниз
  полоса идёт равномерно по всей странице и догоняет прокрутку с затуханием.
  К положению добавлено опережение в треть экрана, иначе блок загорался бы
  у самого верха. Считает только геометрию и ставит `data-live` на строку блока;
- `BusNode` — квадратик и линия до рамки. Отступы считаются от `--bus-box-h`,
  поэтому линия всегда входит ровно в середину рамки;
- `BusLabel` — название блока в рамке. Обесточенная рамка нарисована всегда,
  поверх неё ток идёт двумя симметричными путями из левой середины и
  замыкается в правой. Ширина меряется после загрузки шрифта;
- вся хореография — в CSS, по `[data-bus-row][data-live]`. Первый блок
  страницы помечен `data-static` и запитан сразу, без анимации.

Узел ставится только там, где у секции есть название блока, — иначе линия
уходила бы вправо в пустоту.

## Форма

Своей серверной части у сайта нет. Заявки принимает общий сервис
**forms.genobiz.ru** — он проверяет поля, отсеивает ботов и шлёт письмо.
Сайт остаётся чистой статикой: ни PHP, ни паролей SMTP в репозитории.

Ключ сайта в сервисе — `biokat`. Куда уходит письмо, с каких доменов
принимается запрос и какие файлы можно приложить, задано одним блоком
в `config/sites.php` сервиса. Чтобы сменить получателя, правится он,
а не сайт.

Форма уходит как `multipart/form-data` на `https://forms.genobiz.ru/submit`:
на странице щитового оборудования к заявке прикладывают спецификацию или
однолинейную схему, а JSON файл не унесёт. Служебные поля — `site`,
`form_ts` (метка отрисовки формы) и `website` (ловушка для ботов);
имена заданы сервисом, менять их нельзя.

Заявка, отсеянная антиспамом, получает такой же ответ, как успешная, —
бот не должен понять, что распознан. Настоящая причина видна в журнале
сервиса.

## Где лежит

- **Продакшен** — Beget, домain биокат.рф, сборка в корне сайта;
- **Превью для заказчика** — GitHub Pages: https://vladimir-iti.github.io/biokat/
  Собирается автоматически при пуше в `main` (`.github/workflows/pages.yml`).

Pages отдаёт сайт из подпапки репозитория, поэтому сборка там идёт с
`NEXT_PUBLIC_BASE_PATH=/biokat`: `basePath` подставляется в конфиг, а сырые
пути к файлам в `public/` проходят через `lib/asset.ts`. На своём домене
переменная пуста и всё остаётся в корне. `.htaccess` из превью вырезается:
на Pages он всё равно не работает, а его содержимое отдавалось бы как текст.

## Кэширование

Вечный `immutable` — только у файлов с хэшем в имени (`_next/static`).
Картинки в `public/images/` имя не меняют: замена фотографии обязана доехать
до вернувшегося посетителя, поэтому им отдельное правило на неделю.
Правила живут в двух местах и должны совпадать: `public/.htaccess` (боевой
Apache) и `scripts/serve.ts` (локальная проверка сборки).

Превью закрыто от индексации (`noindex, nofollow`), чтобы не конкурировать
с будущим сайтом в поиске. Форма на превью рабочая: адрес Pages внесён
в `origins` сайта `biokat` в реестре сервиса, поэтому заказчик может
проверить заявку до запуска домена.

## Деплой на Beget

1. Остановить dev-сервер, выполнить `npm run build`.
2. Содержимое `out/` загрузить в `public_html` (SFTP или rsync).
3. Домен подключается как `xn--80abvit0a.xn--p1ai`, сертификат — Let's Encrypt
   в панели Beget.

PHP на сайте больше не нужен: заявки уходят на forms.genobiz.ru, класть
рядом с `public_html` нечего.

`.htaccess` уже лежит в `public/` и попадает в сборку: он делает редирект на
https, склеивает www, приводит адреса к виду со слешем на конце, отдаёт 404
и раздаёт правила кэширования.
